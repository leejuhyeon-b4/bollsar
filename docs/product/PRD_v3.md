# 애배력 PRD v3 — 강홍석 전용 PWA

> **문서 상태**: v2(배우 중심 멀티 배우 플랫폼)를 대체. 최종 목표를 "강홍석 팬 대상 단일 웹앱 배포"로 스코프를 확정 축소.
> **v2 대비 핵심 변화**: 여러 배우를 아우르는 라우팅/확장 전략을 전부 걷어내고, 강홍석 한 명을 위한 PWA 한 개로 확정. "망해도 나 혼자 쓴다"는 원래 안전판 원칙을 가장 단순한 형태로 구현.

---

## 1. 서비스 정의

**강홍석 팬을 위한 개인용 관극 관리 PWA.** 홈 화면에 앱처럼 설치해서 쓰는 웹앱 1개.

- 최종 목표: 강홍석 팬덤 대상 배포
- 최소 성공 기준: 운영자 본인이 실사용, 이후 팬덤 내 배포·확산

### 1.1 v2와의 관계
- v2에서 검증된 결론(경쟁사 분석, OCR 실측 테스트, 정산판 스펙, 이벤트/캐스팅 데이터 분리 원칙)은 그대로 유효
- **폐기되는 것**: 배우별 slug 라우팅, 다중 배우 확장 티어, "배우 여러 명 동시 조회" 기능 — 애초에 배우가 1명뿐이라 불필요

---

## 2. 정보구조 — 탭 2개

| 탭 | 내용 | 로그인 |
|---|---|---|
| **배우 스케줄** | 강홍석 출연 회차 스케줄 + 회차별 이벤트 정보 | ❌ 불필요 |
| **정산판** | 강홍석 고정 관람 집계 (고정 해제 시 공동출연 배우로 전환 가능) | ✅ 필요 (개인 기록) |

- 별도 "내 달력" 탭 없음 — 배우 스케줄 탭 안에서 관극 여부 체크 (v2 원칙 유지)
- 검색 등 그 외 화면은 이번 스코프에서 제외 (탭 2개로 확정)

---

## 3. 배우 스케줄 탭

### 3.1 표시 내용
- 강홍석 출연 회차: 날짜/요일/시간 + **강홍석 배우 사진(작은 썸네일)**
- 회차 이벤트 정보 (첫공무대인사, 커튼콜 특전, 촬영 정책 등) — v2 6장 원칙 그대로 적용
- 회차 클릭 시 상세: 배역, 상대역 배우, 이벤트 상세, 관극 여부 체크 + 좌석 입력
- **오프라인 스케줄** (행사, 영화 무대인사, 팬미팅 등 뮤지컬 회차 외 공개 일정)도 같은 탭에 함께 표시
  - 배역/캐스팅/좌석배치도 개념 없음 — 제목, 일시, 장소, 설명 정도의 단순 정보
  - 정산판 집계 대상 아님 (확정). 참석 횟수 카운트 기능은 추후 별도 구현 예정 (8장 오픈 이슈 참고)

### 3.2 사진 vs 시간 표시
- 회차는 시간으로 표시하고, 강홍석 사진은 배경 투명도 처리 또는 옆 배치 등으로 병기
- 구체적인 배치/스타일은 별도 디자인 프로세스에서 결정 (본 PRD 범위 밖)

### 3.3 데이터 소스
- 관리자가 공연 스케줄/이벤트 이미지 업로드
- **1차: 무료 OCR(네이버 클로바 등) 시도 → 2차: 결과 부정확 시 관리자 수동 입력으로 전환**
- v2의 Claude API 방식과 다른 점: 비용 최소화를 위해 무료 OCR 우선 검토. 실패율 높으면 Claude API 반자동 방식(v2 6장)으로 전환 가능

---

## 4. 정산판 탭

### 4.1 기본 동작
- **강홍석 고정**이 기본값 — 앱 진입 시 강홍석 관람 집계가 바로 보임
- 유저가 고정 해제하면 같은 작품 공동출연 배우 기준으로 정산판 전환 가능
- 집계 방식, 좌석배치도, 색상 스펙은 v2 7장과 동일:
  - 배우별 단순 관람 횟수 (`/N회`), 페어 정산 아님
  - 좌석배치도는 등급색 없이 단색, 방문한 좌석만 유저가 고른 색으로 표시, 방문 횟수별 진하기 자동 단계화
  - 완성본 이미지 캡처 가능

### 4.2 사진
- 정산판에 쓰이는 배우 사진도 **관리자가 업로드** (v2처럼 별도 이미지 검색/자동 수집 없음)

---

## 5. 데이터 모델 (축소판)

멀티 배우 확장을 걷어냈지만, 공동출연 배우는 정산판 고정 해제 기능 때문에 여전히 필요함. v2 스키마에서 다음만 유지:

```
works (작품) — id, title, start_date, end_date, poster_image
roles (배역) — id, work_id, role_name
performances (회차) — id, work_id, date, time, is_first_perf, is_no_show
performance_casts (회차별 배역-배우) — id, performance_id, role_id, actor_name, actor_photo
performance_events (회차 이벤트) — id, performance_id, event_type, description, photo_policy, is_verified
seat_maps (작품별 좌석배치도) — id, work_id, layout_data
offline_schedules (오프라인 스케줄: 행사/무대인사/팬미팅 등) — id, title, event_type, date, time, location, description, photo
my_records (개인 관극 기록, RLS 본인만) — id, user_id, performance_id, seat_id, checked_at
```

- `actors` 테이블은 별도로 두지 않고 `performance_casts`에 배우 이름/사진을 직접 저장 (배우 중심 확장이 없으므로 정규화 불필요, 단순화)
- 관리자 전용 업로드이므로 `report_flags`(유저 제보) 테이블은 이번 스코프에서 보류 — 필요성 재검토 필요 (관리자가 직접 다 채우면 제보 체계 자체가 불필요할 수 있음, 8장 참고)

---

## 6. 로그인 경계

- 배우 스케줄 탭 조회: 비로그인
- 관극 체크 + 좌석 입력 + 정산판: 로그인 필요
- 관리자 업로드(스케줄/이벤트/사진): 별도 관리자 권한 (일반 유저 로그인과 분리)

---

## 7. 기술 스택

- Next.js, TypeScript, Tailwind CSS, **PWA 설정** (manifest, service worker, 홈 화면 설치)
- Supabase (Auth + Postgres)
- Vercel
- OCR: 네이버 클로바(무료) 우선 시도 → 실패 시 관리자 수동 입력 (Claude API는 백업 옵션으로 남겨둠)

---

## 8. 오픈 이슈

1. **네이버 클로바 OCR 정확도 검증** — 캐스팅표/이벤트 공지 각각에 대해 실측 테스트 필요 (v2에서 Claude API로 테스트했던 것과 동일한 방식으로 클로바도 검증)
2. **정산판 고정 해제 시 UX** — 공동출연 배우로 전환할 때 배우를 어떻게 선택하게 할지 (드롭다운/탭 등, 디자인 단계에서 결정)
3. **강홍석 손글씨 에셋 적용** — 배포 직전 마지막 단계로 보류. 전체 폰트화는 한글 특성상 샘플 수백 자 이상 필요해 비현실적이므로, 고정 문구(로고/타이틀 등)에 이미지로 삽입하는 방식(A안)으로 한정. 초상/성명 관련 이슈는 배포 전 별도 확인 필요
4. **무대인사 등 오프라인 스케줄 참석 횟수 카운트** — 정산판(좌석 기반)과는 별개 기능. 이번 스코프에는 포함하지 않고 추후 구현 예정

> 배치/스타일 등 디자인 관련 사항은 본 PRD에서 다루지 않고 별도 디자인 프로세스에서 결정

## 9. 마일스톤 (초안)

1. Supabase 스키마 구축 (5장)
2. 강홍석 출연작(현재: 엘리자벳) 스케줄+이벤트+오프라인 스케줄 관리자 수동 입력
3. 배우 스케줄 탭 구현 (비로그인)
4. 로그인 + 관극 체크 + 정산판 탭 구현
5. PWA 설정 (설치 가능하게)
6. 네이버 클로바 OCR 연동 테스트 → 정확도 낮으면 수동 입력 유지
